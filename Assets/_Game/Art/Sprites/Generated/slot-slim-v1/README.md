# 卡槽边框「收细」v2 —— 2026-09-23

## 这轮解决什么

用户在上一步（`Generated/slot-v1` 的卡槽底板 v6）之后只说两个字：**「收细」**。

收的是**边框的墨量**。装上的 v6 与工程原有线层叠在一起，边框实际上是 **3 条同心带**：

| 来源 | 素材 | 带的位置（sprite px，从槽边数起） | 屏上位置 |
|---|---|---|---|
| 底板亮边 | `SlotPlate.png` | 0–5，alpha 204 | 0.00–1.16 px |
| 线层外线 | `SlotEdge.png` | 7–11，alpha 255 | 1.35–2.21 px |
| 线层内线 | `SlotEdge.png` | 15–18，alpha 161 | 2.89–3.56 px |

整条边框横跨 **12 sprite px ≈ 3.6 屏幕 px**，三段亮度都接近满值 —— 高亮态读起来是一条又粗又花的边。
（这也是「收细」和 `SlotEdgeOverlay` 一起被提出的原因：线层是唯一还会在高亮态显形的第二层。）

## 改了什么

**只动边框，别的一律不动。** 底板公式与 v6 逐字相同（底色 0.22、上内影 22 / 左 14 / 下 18 / 右 12），
唯一差别是亮边参数 `RimBand` / `RimA`；线层从双线改成**一条贴边单线**，并沿底板真实轮廓取等距（同心同形）。

| 项 | 改前 | 改后（收细②） |
|---|---|---|
| 底板亮边 | 6 px @ 0.80 | 3 px @ 0.46 |
| 线层 | 双线 5px@1.00 + 4px@0.63 | 单线 4px @ 1.00 |
| 边框总跨度 | 12 sprite px（3 条带） | 4 sprite px（2 条带） |
| 屏上厚度 | 2.3 px | 0.77 px |
| 边框总墨量 | 100% | 约 33% |

**已安装**（`Assets/_Game/Art/Sprites/Board/`）：

- `SlotPlate.png` ← `Generated/slot-slim-v1/Plate_v7_b.png`
- `SlotEdge.png` ← `Generated/slot-slim-v1/Edge_v7_b.png`

两个 `.meta` 都没动（guid 不变）→ prefab `Slot_0.prefab` 与场景零改动。
> **顺带修掉一处不同心**：旧的 `SlotEdge.png` 是自己画圆弧、圆角半径取 55 sprite px；
> 而底板真实轮廓的圆角半径实测是 **61 sprite px**（最小二乘拟合 91 个边界点，rmse 0.96 ≈ 11.7 屏幕像素）。
> 新线层不再自画圆弧，而是与底板共用同一张轮廓遮罩、按距离场取等距 → **两者完全同心同形**。

## 已知偏差（别当 bug）

- 实机截图那条链路本身有约 2–3 屏幕像素的模糊（卡的边缘同样是 3 px 过渡），
  所以**实机里线会比预览图再软一点**；预览是按素材真实 alpha 合成的「理想锐度」。
- 高亮态的颜色按「UGUI 顶点色在线性空间直接相乘」建模（`UI/Default` 的 `tex2D * i.color`，`Graphic.color` 无 `[Gamma]`），
  黄取线性 `(1, 0.92, 0.0157)`。若实机偏暗/偏亮，是这一层口径的问题，与素材无关。

## 生成脚本

- `Tools/cardframe/SlotSlimV7.ps1` —— 轮廓遮罩（`Get-Mask`）/ 距离场（`Get-MinDist`）/ 底板（`New-PlateAlpha`）/ 线层（`New-EdgeAlpha`）/ 落盘（`Save-Alpha`）。
- `Tools/cardframe/SlotSlimPreview.ps1` —— 反解 + 前向合成 + 出 1:1 预览。

> 坑：PowerShell 变量名大小写不敏感，`$d` 与 `$D`、`$sw` 与 `$SW` 是同一个变量（本轮两个都踩过）；
> `$a += (数组)` 会把数组拍平，要写成 `$a += ,(数组)`。
