## 一、要一份「共享存储」才能做的两件（自建后端 / 第三方）

这两件都不是坏了，是**没做** —— 不做也不影响现在能跑的东西。
它们**不共用一张表**，是两件事，可以先做其中一个。

### 1. 拉黑里「他拉黑了我」那半边

- **现状**：`FriendBlock.BlockedByLookup`（`Assets/_Game/Scripts/UI/Lobby/FriendBlock.cs`）是改造位，**恒 null ⇒ `BlocksMe` 恒 false**。
  我拉黑的人**已经**完整生效（搜不到 / 加不了 / 申请进不来 / 匹配不受影响）；缺的是**反方向**：A 拉黑 B 之后，
  **B 那边**还能搜到 A、还能单向把 A 加成好友（A 看不到 B，所以只是 B 自己那儿多一条假的）。
- **为什么本地解决不了**：拉黑是「我不想让你看见我」，不能靠被拉黑方反向去问 —— 问了就等于告诉他被拉黑了。
  必须有个**第三方**存那份名单。Steam 侧也给不了：Web API 没有「查别人的黑名单」这种接口。
- **要什么**：一张黑名单表 + 一个查询。查询只回**隐藏 / 不隐藏**，**不解释原因**（与「不告诉对方你被拉黑了」那条口径一致）。
- **接上时改哪**：装一处 `FriendBlock.BlockedByLookup = (playerId, steamId) => 查询(...)`。
  `IsHidden` 的双向性会自动成立（搜索那 3 处 + `Accept` 守卫都已走 `IsHidden`），UI 一行不用改。
- **语义要接受**：拉黑**有延迟** —— 拉黑方什么时候上线把名单同步上去才算数；他离线期间拉的，对方在他上线前仍看得见。
- **退路**：就保持现在这样（只做本地半边）。

### 2. 按**昵称**全服搜玩家

- **现状**：「添加好友」只能搜到（a）**异界号**（本地就能解出 SteamID64，精确命中）和（b）**已知玩家**
  （好友表 ∪ Steam 好友）的昵称/号片段。全服按昵称搜做不到。
- **为什么**：Steam **没有**按昵称搜人的接口。跟昵称沾边的只有 `ISteamUser/ResolveVanityURL`，
  那是把**自定义主页地址**（`steamcommunity.com/id/xxx`）解成 SteamID64，不是搜昵称。
- **要什么**：一份「昵称 → 异界号」的**玩家目录**（玩家上线时登记；查询按昵称模糊匹配）。
  这块比第 1 件贵：要防刷、防爬、还要处理**重名**。
- **接上时改哪**：分界线就在 `FriendAddSearch.KnownPlayers()`（`Assets/_Game/Scripts/UI/Lobby/FriendAddSearch.cs`）——
  把「已知玩家」换成「目录查询」即可，上面那层的状态机 / 结果行不用动。
- **退路**：**干脆不做** —— 只按 ID 加好友（现在就能用），这也符合已定的口径「加好友只需游戏内的即可」。

### 备忘：这两件事的成本口径（2026-09-27 查过）

- **机器配置不高**：数据量随玩家数线性（1 万玩家 ≈ 几 MB，10 万 ≈ 几十 MB），请求量也低。
  最低档 VPS（1 核 / 1G）够几万玩家；serverless 免费档在这个量级基本 ¥0。SQLite 就够。
- **麻烦的不是机器**，是四件事：① 必须**验身份**（伪造异界号就能读写别人的数据），标准做法是 Steam 票据校验
  `ISteamUserAuth/AuthenticateUserTicket` —— **这一步恰好要用 publisher key**；② 有个常开的进程要养
  （部署 / 日志 / 域名 / 证书，国内还要备案）；③ 拉黑的**延迟语义**（见上）；④ 存的是别人的昵称与关系数据，要有隐私说法。
- **所以「拿 key」和「自建后端」最后是绑在一起的**，不是二选一。

## 二、拿到 Steam Web API key 就能做（**不需要**后端）

### 3. 好友表「拥有即加」

- **现状**：没有 key 时，「对方玩过本游戏」只认三条**运行时**证据（正在玩 / 我俩一起玩过 / 我们见过他）。
- **拿到 key**：装 `FriendEvidence.OwnedLookup`（`Assets/_Game/Scripts/UI/Lobby/FriendFilters.cs`）=
  `IPlayerService/GetOwnedGames` 的查询，就自动多一条「**拥有即收录**」。
- **改造位已经留好了**：`FriendListService` 那条规则链不用改，装上就生效（`HasOwnedLookup` 会变 true）。

### 4. 「添加好友」支持粘 Steam 主页链接

- **做法**：输入框里粘 `steamcommunity.com/id/xxx`（或 `/profiles/7656...`）时，用 `ISteamUser/ResolveVanityURL`
  解成 SteamID64 → 走现成的「按 ID 加好友」那条路。
- **价值**：不用对方先给出异界号也能加（Steam 好友之外的场景）。
- **不解决第 2 件** —— 它是「地址 → 人」，不是「昵称 → 人」。

## 三、能跑，但还没验过

### 5. 好友申请的真·双机收发

- **现状**：包逻辑（编 / 解 / 五道门 / 落到申请列表）与「收包泵自己装上了」都已自证
  （`stage71b_friend_request_channel.txt` OK 27/0、`stage72_pump_boot.txt` OK 4/0）。
- **没验的**：真实的「一台机器发出去 → 另一台收到」。要件：两台登了 Steam 的机器（或两个 Steam 账号）。
- **可选**：先做一个**本机回环**自测（同一个账号给自己发）把那截也盖上 —— 只能证明通道通，不能证明跨账号。
