# 发版流程（Release Runbook）

> 目标：把当前 `main` 的 Windows 单机包发布成 GitHub Release（`vX.Y.Z`）。
> 实测样本：**v0.2.1（2026-09-25）**，从改版本号到 Release 可下载约 **8 分钟**（其中 360 MB 上传约 2 分钟）。
> 一键入口：`Tools/Release.ps1`；本文既是它的规格说明，也是手动兜底步骤。

## 0. 一句话流程

改 `Assets/_Game/Scenes/Welcome.unity` 的 Inspector 版本号 → commit + push 到 `main`
→ tag / 构建 / 上传 Release **全部自动**（不需要手动建 tag）。

## 1. 前置条件

| 项 | 要求 | 检查方式 |
|---|---|---|
| 源仓库 | workflow 里取源路径写死为 `C:\Users\22589\Documents\GitHub\Another-World` | 换机器必须同步改 workflow |
| self-hosted runner | `win-build`（`C:\actions-runner`）处于 Listening | `Get-Process Runner.Listener`；`C:\actions-runner\run-stdout.log` 出现 `Listening for Jobs` |
| Unity | `C:\Program Files\Unity\Hub\Editor\2022.3.62f2c1\Editor\Unity.exe`（workflow 写死） | 版本不符要改 workflow |
| 推送权限 | 本机 git 凭据可 push `origin`（https） | `git push --dry-run origin main` |
| Unity 编辑器 | **可以开着**：构建在 runner 工作区里跑，不碰本仓库 | — |

> runner 是最容易翻车的一条：它不在时任务会一直 `queued`（`run_started_at == created_at`），GitHub 不报错，看起来只是"卡住了"。

## 2. 一键发版

```powershell
Tools\Release.ps1 -Version 0.2.2            # 会先打印将执行的动作并要求确认
Tools\Release.ps1 -Version 0.2.2 -Yes       # 跳过确认
```

脚本做的事（= 手动流程的全部）：

1. 检查 self-hosted runner，没在跑就 `Start-Process run.cmd -WindowStyle Hidden` 拉起来；
2. 把 `Assets/_Game/Scenes/Welcome.unity` 里的 `  currentVersion: <旧>` 改成 `<新>`（**只改这一行**）；
3. `git add` 该文件 → `git commit -m "<新版本>"` → `git push origin main`；
4. 轮询 GitHub（走 release 页面，不占 API 限额）直到 tag 出现、`Another-World-Windows.zip` 挂上 Release，最后 HEAD 校验下载链接。

前置检查会拦住三种常见误操作：分支不是 `main`、版本号没变、远端已有同名 tag。

## 3. 触发链（为什么 push 一下就够了）

```
push main（本次改动必须包含 Assets/_Game/Scenes/Welcome.unity）
   └─ auto-release.yml :: check-and-tag
        ① 从本机仓库同步源码（不用 actions/checkout：工作树约 730 MB，浅克隆会卡住发版）
        ② 读 Inspector currentVersion → 远端没有 v<版本> → 建 tag 并 push
        ③ 同一个 job 内接着跑（条件 TAG_CREATED == 'true'）：
           Write version.txt → Copy Library cache（从本仓库拷，免一次 full resolve）
           → Fix up UPM ProjectCache（改绝对路径 + 重算 md5）
           → Unity -batchmode -nographics -buildWindows64Player
           → Zip Build → softprops/action-gh-release
```

两个容易误解的点：

- **`build-release.yml` 不会触发。** tag 是 workflow 用 `GITHUB_TOKEN` 推的，GitHub 不为 `GITHUB_TOKEN` 的推送再触发其它 workflow —— 所以构建步骤内联在 `auto-release.yml` 里。`build-release.yml` 只作为手动补建的备份入口（手动推 tag 才会走它）。
- **同版本重复 push 不会重建。** tag 已存在 → `TAG_CREATED=false` → 构建相关步骤整段跳过（只留一次"空跑成功"）。要重发就换版本号。

## 4. 版本号落在哪

| 位置 | 作用 | 谁写 |
|---|---|---|
| `Assets/_Game/Scenes/Welcome.unity` 的 `currentVersion`（Inspector） | **发版源**：workflow 用它决定 tag 名 | 人（第 2 步） |
| `Assets/_Game/Resources/version.txt` | **包内实际显示与更新校验**：`UpdateManager.Awake` 读它覆盖 Inspector 值 | 构建时由 workflow 写；不入库 |

## 5. 验收

**取回 tag**：`git fetch --tags origin`

**确认 tag 指向本次版本提交**：`git for-each-ref --format="%(refname:short) -> %(objectname:short)" refs/tags/<新版本>`

**Release 页**：`https://github.com/xinxiangheart/Another-World/releases/tag/<新版本>`

**资产**：`Another-World-Windows.zip`。对下载链接发 HEAD，`Content-Length` 应等于本机 zip 字节数（v0.2.1 = 377,962,058 B ≈ 360.5 MB）。

## 6. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 任务长期 `queued` | self-hosted runner 没在跑 | 在 `C:\actions-runner` 下把 `run.cmd` 以隐藏窗口后台启动，等 `run-stdout.log` 出现 `Listening for Jobs` |
| tag 有了，Release 里没 zip | 360 MB 上传慢，`Create Release` 步骤要几分钟 | 继续等；看 `C:\actions-runner\_diag\Worker_*.log` 最后一条 `Processing step` |
| 构建失败 | Unity 报错 | 看 runner 工作区 `C:\actions-runner\_work\Another-World\Another-World\build.log`（`Show Build Log` 只在 failure 时打） |
| 改了版本号但没动静 | push 里没有 `Welcome.unity` 这个路径 | workflow 只按这个文件过滤，确认改动已提交并推送 |
| 发错了版本号 | — | 在 GitHub 网页端 Tags 里删掉 tag 后重发 |

## 8. 相关文件
