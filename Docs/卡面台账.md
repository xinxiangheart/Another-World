## 4. 外圈边带体检（2026-09-25 实测）—— 待重出队列

**测法（可复现）**：在每张图「外圈 46px 边带」内均匀抽样，统计 `alpha > 8` 的像素占比 r。
- r = 0% → 合格

- r ≥ 85% → 满幅（背景铺到画布边）

## 7. 脸部质量（2026-09-26 实测）—— 全库最大的一块债

**病灶**：用户 2026-09-26 判定「脸画的非常难看」，并指出「其实群狼之王的卡图算是好的了，其它卡图更差劲」。逐张放大核对后确认：**全库没有一张脸达到参考标准**，`01504` 只是「库里最好」，不是「好」。

**实测证据**

| 项 | 库内 | 用户 `脸部参考.docx`（31 张） |
|---|---|---|
| 画面里「暖色皮肤」占比（中位） | 1 费 **0.4%** / 3 费 **0.1%** / 5 费 **3.2%** | **9.5%** |
| 上睑线 | `01504`：粗楔形，外眼角不钩、无睫毛 | **细到中等的一条深色线**，外眼角**收成一个短而细的尖**（**不外飞成猫眼、无独立睫毛尖**） |
| 虹膜 | `01504`：**一块平色**，被上睑切掉约 **40%**，无瞳孔无高光 | **一块基色 + 边缘一圈略深 + 中间略亮 + 一枚小高光（约虹膜 1/10，偏上）** |

**规则层已改（2026-09-26）**：`AGENTS.md`「脸模」条重写 —— 脸模基准由 `01504` 换成用户 `脸部参考.docx`（31 张），`01504` 降级为全身构图 / 气质 / 明度的库内锚。

**同日二次修（重要）**：第一版把参考图的细节**读成了硬指令**，按它出的 `01101` 三张被用户判为「**这是什么猎奇脸模**」—— 病灶是 `thick black lash line + hooks up and out + 2–3 lash spikes`（⇒ 浓眼线）、`soft blush`（⇒ 浓腮红）、`one big bright pure white highlight`（⇒ 洋娃娃眼）。**现收窄为**：脸只留三样软化（虹膜边缘略深 + 一枚小高光 + 一条浅上睑褶线），**腮红、浓眼线、睫毛尖重新禁**。上表的「参考」一列已按放大实测改写（旧值写错了）。

**由此产生的重出队列（用户 2026-09-26 确认）**：全库 **136 张召唤物卡图几乎都要重出**（不只是第 4 节那 63 张边带不合规的）—— 因为旧图全部是照「脸部全硬边 / 禁腮红 / 禁软过渡」的旧口径画的。**但这是未来计划，现在不开工**；开工前先与第 4 节（63 张边带）、第 5 节（法术口径）一起排优先级。

**外部参考件**：`图片参考.docx`（背景 / 视角 / 细节，32 张）与 `脸部参考.docx`（脸，31 张）—— 都在桌面，索引与分工见 AGENTS.md「参考件索引」。

**工具**：`Tools/cardface/gate_check.py` —— 三道门 + 第 4 道门；未抠图的洋红底候选也能直接量（无 alpha 时按四角键色推定背景）。

**四条设计轴的债（2026-09-26 实测，用户判「服装 / 特效 / 角色细节 / 脸与头发 完全不合格」）**：拿 `Tools/cardface/design_check.py` 扫全库 **135 张：判退 131 / 仅警告 3 / 过关 1（`01301` 小丑）**。逐轴不达标率：**高饱和 84%**（我方中位 **0.2%**，商业 11.9%）、**最亮块 77%**（0.1% vs 8.8%）、**明度阶梯 76%**（4 vs 8）、**细节密度 70%**（7.1 vs 13.1）、色相簇 55%、近黑 38%。同口径商业 109 张 71% 过关、三国杀 20 张 75% 过关。

**根因（写在规则自己身上）**：旧提示词底盘里的 `low saturation / no gradients / simple clean shapes / low detail density` 四条，正好把四轴全禁掉 —— 连 5 费的「换 `low saturation`」变体也救不回来（`01507` 生命祭司平均饱和仅 11.1）。**2026-09-26 已换底盘**（正向要：饱和点缀色 / 发光特效 / 金属宝石高光 / 多层服装 / 高细节密度），并把「低细节密度」「禁渐变 / 禁辉光」「高饱和 ≤0.15」三条作废，见 AGENTS.md「四条设计轴」。

**校准实测（2026-09-26，2 张草稿）**：按新底盘出 2 张，**同脸尺度下细节密度 27.3 / 26.9（现役库 7.9–19.6）、高饱和 9.9% / 6.2%（现役库 0.0–7.2%）** —— 细节与饱和度一次进带；**明度阶梯（仍 3–4）与近黑仍未进带**，这一轴要在服装描述里落实（见 AGENTS.md「四条设计轴」→「校准实测」）。同时实测出两条新失效模式：模型会**往画面里塞文字 / UI**（出了「ABYSSAL WEAVER / LVL 99」铭牌）、**主体会铺到四角**（占掉下两角 3%）—— 两条对策已写进该节。脚本 Tools/cardface/refs/design_compare.py。
**已知限制（2026-09-26 已定方向，见 AGENTS.md「商业化卡面基准（召唤物）」）**：卡面画窗实测 `ArtworkArea = 64 × 84`（`Assets/_Game/Prefabs/Cards/Summon/Card00_New_2D.prefab`），1152 → 64 缩放 **0.0556** —— 卡面上脸约 **9.7px**、虹膜约 **1.2px**。即在**卡面尺寸下全身构图任何画法都读不出五官**。

**结论（2026-09-26）**：不靠「放大看」补救，靠**取景**补救 —— 人形一律**半身偏七分（3–5 头身、头 ≥ 画窗 1/5 高）**，`全身` 只留给非人形；同时补 `thumbSD ≥ 40` 与「暖色皮肤 ≥ 3%」两道可测门。**这条一并进上面那 136 张的重出队列** —— 重出时要按新取景重新构图，不只是重画脸。
